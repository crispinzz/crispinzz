## About

```text
◈  Role       →  Developer / Product Builder
◈  Focus      →  Software / Products / Automation
◈  Approach   →  Build / Test / Improve
```

I build software and explore the path between an idea and a product that actually works.

I'm interested in understanding the problem behind it, deciding what should be built, shaping the interface, testing assumptions and improving what happens after the first version is running.

For me, development is less about collecting technologies and more about using them to turn ideas into something concrete.

## What I'm Building Toward

I like projects where I can understand more than one isolated piece of the system — not just the code, but the decisions around it.

```text
Problem → Product → Interface → Code
                                  ↓
Feedback ← User ← Integration ← Automation
```

That means exploring how software behaves outside the editor — when someone actually depends on it, finds a problem, expects something faster or uses it differently than expected.

---

## Principles

```text
→ Understand before adding
→ Build before overengineering
→ Test before assuming
→ Keep complexity when it earns its place
→ Fix the problem, not only the symptom
→ A working version teaches more than an untouched idea
```
